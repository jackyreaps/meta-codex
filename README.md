# meta-codex

A Lean 4 metaprogramming library and formal framework for **structural realism in higher-dimensional abstractions**: auditing whether recursive towers, layered structures, and existential fibers carry genuine mathematical necessity rather than acting as passive type-level scaffolding.

> *"The solution is a topologically true artifact—a perfectly consistent construct generated by a higher dimensional differential argument—which simultaneously embodies a 'looks true' paradox."*

**Keywords:** Lean 4 · metaprogramming · formal verification · proof auditing · dependency cone · transitive dependencies · vacuous definitions · `opaque` declarations · structure field projection · unused hypotheses · existential fibers · underdetermination · proof irrelevance · inductive types · Mathlib-compatible

## Overview

In dependent type theory, kernel acceptance guarantees **local type inhabitance**, not **structural necessity**. Proof irrelevance (`P ∧ True ↔ P`) and existential quantification (`∃ L, …`) let deep recursive hierarchies pass type-checking while forwarding vacuous witnesses or unidentifiable structural fibers. `meta-codex` pairs metaprogramming audits with formal underdetermination models.

### Audit commands

| Command | What it reports | Module |
|---|---|---|
| `#audit_theorem T` | Walks `T`'s transitive dependency cone, opening `opaque` bodies too, and flags definitions that reduce syntactically to `True`, `opaque` boundaries, and custom axioms | `Core/ConeAudit.lean` |
| `#audit_fields T S` | For each field of structure `S`: whether it is opened (`Expr.proj`, its accessor, or `S.rec` / `casesOn`) anywhere in `T`'s cone, or only carried along as passive payload | `Core/FieldProjection.lean` |
| `#audit_passthrough T` | Declarations in `T`'s cone that accept a `Prop` hypothesis and never use it in their proof | `Core/PassThroughAudit.lean` |
| `#audit_fibers T` | `Exists`-quantified signatures in `T`'s cone that may hide structural parameters before the conclusion | `Abstractions/ExistentialFiber.lean` |
| `#audit_inductives T` | Mutual and nested inductive types in `T`'s cone whose `numParams` metadata disagree | `Abstractions/InductiveIntegrity.lean` |

How the cone is walked:
- **Theorem and `opaque` bodies are followed.** Every cone walk reads values with `ConstantInfo.value? (allowOpaque := true)`, so a proof body or an `opaque` wrapper cannot hide part of the dependency graph.
- **Library constants are skipped by module.** A constant is skipped when it comes from an imported library module (`Init`, `Lean`, `Std`, `Mathlib`, `Batteries`, `Aesop`, `Qq`, `ProofWidgets`, `Plausible`, `ImportGraph`), using `Environment.getModuleIdxFor?`. This catches core lemmas whose names don't start with a library prefix, such as `Nat.add_comm` and `Exists.intro`. All the walks share one rule: `isExternalLibraryConst` in `Core/ConeAudit.lean`.

### Formal models (all `sorry`-free, pure Lean 4 core)

## Quickstart

### Build and run the examples

meta-codex depends on nothing but Lean itself.

```bash
git clone https://github.com/jackyreaps/meta-codex
cd meta-codex
lake build          # every library and both examples; the audit reports print as build messages
```

Excerpt from `Examples/HigherDimDemo.lean`:

```text
[VACUOUS] `MetaCodex.Examples.vacuousManifoldTag` reduces syntactically to `True`.
[OPAQUE BOUNDARY] `MetaCodex.Examples.opaqueVacuousTag` is declared `opaque` (body inspected via `allowOpaque := true`).
[OPENED]   MetaCodex.Examples.LayeredManifold.activeBound
[UNOPENED] MetaCodex.Examples.LayeredManifold.passiveTag (carried in cone but never projected or eliminated)
[UNUSED HYP] `MetaCodex.Examples.demoHeadlineTheorem` never references `Prop` binder(s): [_hf]
```

### Use it in your own project

Add to your `lakefile.toml`:

```toml
[[require]]
name = "meta-codex"
git = "https://github.com/jackyreaps/meta-codex"
rev = "main"
```

Then, in any Lean file:

```lean
import MetaCodex

#audit_theorem myHeadlineTheorem
#audit_fields myHeadlineTheorem MyLayeredStructure
#audit_passthrough myHeadlineTheorem
#audit_fibers myHeadlineTheorem
#audit_inductives myHeadlineTheorem
```

The pinned toolchain is Lean v4.30.0. The code also builds unchanged on v4.33.1. On recent Lean versions `value?` hides theorem bodies unless `allowOpaque := true` is passed, which is why every walk passes it.
